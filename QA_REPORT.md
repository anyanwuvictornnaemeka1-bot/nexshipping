# Nexshipping Engineering QA Report

**Date:** 17 September 2026  
**Scope:** Engineering QA of the current Nexshipping GitHub repository after the frontend changes. The review focused on correctness, API/database behavior, authentication, security, responsive behavior, and production readiness rather than visual redesign.

## Executive summary

Nexshipping passed the final reproducible verification pass. The frontend and backend production bundles build successfully, TypeScript and ESLint are clean, all 12 automated tests pass, the configured database is reachable with all expected application tables present, all public smoke routes return HTTP 200, and malformed tracking input returns HTTP 400. Production-mode probes confirm that unauthenticated admin access returns HTTP 403 and does not expose a stack trace. The final production dependency audit reports **no known vulnerabilities at low severity or above**.

Two real engineering issues were fixed. Local HTTP session-cookie clearing now uses a browser-compatible `SameSite=Lax`/non-secure policy while HTTPS retains secure cross-site cookies. Session verification now rejects tokens issued for a missing or different application ID and fails explicitly when `JWT_SECRET` is absent. The repository also gained a real `pnpm lint` gate, regression coverage for contact and newsletter validation, and dependency remediation for previously reported high, critical, and denial-of-service advisories.

## Changes made

The authentication changes are in `server/_core/cookies.ts`, `server/_core/sdk.ts`, `server/_core/context.ts`, and the associated tests. Cookie policy is now derived from the request protocol, and session tokens cannot be accepted across application IDs. The client auth hook also handles restricted session storage without an empty catch block.

The repository now has `eslint.config.mjs` and a `lint` package script. Unused imports and bindings found during the first lint pass were removed without changing product behavior. Public API validation tests were added in `server/nexshipping.test.ts` for contact and newsletter requests.

The dependency remediation updates AWS SDK, tRPC, Drizzle ORM, Axios, MySQL2, Nanoid, Streamdown, and patched Lodash packages. The `.pnpmfile.cjs` hook moves Express to patched `body-parser`, `qs`, and `path-to-regexp` versions. The existing Wouter route-discovery patch remains recorded in `pnpm-lock.yaml`, and a frozen-install check verified that the patched package is installed.

## Remaining caveats

No authenticated OAuth browser session was available during this QA run, so a real admin shipment mutation was not submitted through the live UI. This was intentional: the shared database was not seeded or populated with mock shipment, quote, contact, or subscriber records. Protected procedure authorization and validation were tested without creating persistent test PII.

The active sandbox uses pnpm 10.4.1 and prints a non-blocking warning that the legacy `pnpm.patchedDependencies` package field is ignored. The committed lockfile remains valid, the frozen install succeeds, and the Wouter patch is installed correctly. A future dependency-refresh workflow should use a newer pnpm release that natively reads workspace settings before regenerating the lockfile.

## Final conclusion

The repository is in a releasable engineering state for the requested scope. No API request rewrites, database-call regressions, authentication bypasses, authorization failures, production error leaks, or high-severity dependency findings were left unresolved. The only noted follow-up is performance-oriented client chunk splitting and a future pnpm toolchain refresh; neither blocks the current production build or runtime behavior.
